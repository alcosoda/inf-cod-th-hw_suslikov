# Расширенный формат описания источника

Расширение исходного JSON-формата задачи 1.1. Позволяет описать:
- марковский источник глубины *d* над алфавитом мощности *k*;
- стационарный неэргодический источник;
- исходный формат — как частный случай: **любой файл исходного формата является корректным файлом расширенного формата** и читается без конвертации.

## 1. Грамматика

```
источник     ::= переключаемый | марковский | смесь

переключаемый ::= { ["type": "switching",]          -- поле type можно не писать
                    "models":   { имя: распределение, ... },
                    "switches": { имя: { имя_модели: вероятность, ... }, ... },
                    "source":   [ имя_переключателя, ... ] }

марковский   ::= { "type": "markov",
                   "order": d,                       -- целое >= 1
                   "initial":     { состояние: вероятность, ... },
                   "transitions": { состояние: распределение, ... } }

смесь        ::= { "type": "mixture",
                   "components": [ { "weight": вероятность, "source": источник }, ... ] }

распределение ::= { символ: вероятность, ... }       -- сумма ровно 1
состояние    ::= "s1 s2 ... sd"                      -- d символов через пробел
вероятность  ::= строка: "p/q" | десятичная запись   -- "1/3", "0.25", "1e-3"
```

В любом описании (в том числе вложенном) допускается необязательное поле `"description": "текст"`.

## 2. Семантика

Такты нумеруются с нуля: символ *X*₁ порождается на такте 0, *X*ₜ — на такте *t*−1.

**`switching`** (исходный формат). На такте *i* берётся переключатель `source[i mod L]`, по его распределению выбирается модель, по модели — символ. Выборы на разных тактах независимы. Значит, символы независимы, а распределение символа периодично по *i* с периодом *L*.

**`markov`**. Первые *d* символов выбираются **одним** выбором — состоянием из `initial`. Затем каждый следующий символ выбирается по строке `transitions[последние d символов]`. Состояние сдвигается: (*s*₁,…,*s_d*) → (*s*₂,…,*s_d*, новый символ). Это источник с памятью глубины *d*.

**`mixture`**. **Один раз**, до первого такта, по весам `weight` выбирается компонента. Дальше все символы порождает только она. Компонентой может быть источник любого типа, в том числе другая смесь.

**Период** для режима 2 (величина «среднее по позициям внутри периода»):
`switching` — *L*; `markov` — 1; `mixture` — НОК периодов компонент.

## 3. Почему смесь даёт неэргодичность, а исходный формат — нет

В исходном формате каждый такт разыгрывается **заново и независимо**, никакой случайный выбор не действует дольше одного такта. Поэтому символы на тактах *i* и *i*+*L*, *i*+2*L*, … независимы и одинаково распределены. По усиленному закону больших чисел частота любого блока в **одной** реализации почти наверное сходится к **неслучайному** числу, то есть к среднему по периоду. Это эргодичность: её нельзя нарушить никаким выбором моделей, переключателей и `source`.

В смеси выбор компоненты делается один раз и **действует вечно**. Частоты в реализации сходятся к вероятностям **выбранной** компоненты, то есть предел — случайная величина: с вероятностью `weight₁` он один, с вероятностью `weight₂` — другой. Средние по времени не совпадают со средним по ансамблю, а это и есть неэргодичность. Если все компоненты стационарны, смесь стационарна: её конечномерные распределения — взвешенные суммы стационарных.

## 4. Примеры (вариант *s* = 19: *k* = 4, *M* = 3, *L* = 7, *d* = 2)

Файлы лежат в `tests/sources/`. Алфавит {a, b, c, d}, три модели `m1`, `m2`, `m3`.

| файл | свойство | какая конструкция его обеспечивает |
|---|---|---|
| `var_stationary.json` | стационарный (и эргодический) | все 7 позиций `source` — один и тот же переключатель, поэтому распределение символа не зависит от такта |
| `var_nonstationary.json` | нестационарный | в `source` три разных переключателя с разными распределениями символа, поэтому распределение зависит от фазы такта (период 7) |
| `var_markov.json` | марковский глубины 2, стационарный, **эргодический** | все переходы положительны: цепь неприводима и апериодична; `initial` — её стационарное распределение пар: 1/8 для «x x», 1/24 для «x y» |
| `var_markov_nonstationary.json` | марковский, нестационарный, эргодический | те же переходы, но старт всегда из «a a» |
| `var_mixture.json` | стационарный **неэргодический** | `mixture` из двух стационарных компонент с разными распределениями, выбор компоненты — один раз на всю реализацию |

Фрагмент `var_markov.json`:
```json
{
    "type": "markov",
    "order": 2,
    "initial":     { "a a": "1/8", "a b": "1/24", "...": "..." },
    "transitions": { "a b": { "a": "1/6", "b": "1/2", "c": "1/6", "d": "1/6" }, "...": {} }
}
```

Фрагмент `var_mixture.json`:
```json
{
    "type": "mixture",
    "components": [
        { "weight": "1/2", "source": { "models": {"...": {}}, "switches": { "s": { "m1": "3/4", "m3": "1/4" } }, "source": ["s", "s", "s", "s", "s", "s", "s"] } },
        { "weight": "1/2", "source": { "models": {"...": {}}, "switches": { "s": { "m2": "3/4", "m3": "1/4" } }, "source": ["s", "s", "s", "s", "s", "s", "s"] } }
    ]
}
```

## 5. Проверки при загрузке

Описание отвергается с диагностикой, указывающей путь к ошибке (например, `components[0].source.switches.s: несуществующая модель 'q'`), если:
- вероятность не строка, не разбирается, отрицательна; распределение или веса смеси не нормированы;
- нет обязательного ключа или есть неизвестный; неизвестный `type`;
- ссылка на несуществующую модель или переключатель; пустые `models`, `switches`, `source`, `components`;
- `order` не целое ≥ 1; состояние не из *d* символов; состояние задано дважды; символ марковского источника пуст или содержит пробел;
- для состояния, достижимого из `initial` с положительной вероятностью, нет строки в `transitions`;
- повторяющийся ключ в JSON-объекте.
